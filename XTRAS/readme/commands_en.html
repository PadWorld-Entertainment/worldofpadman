Useful Commands

Force Warmup

The command g_WarmupReady can be used to prevent a game from starting immediately after loading, but instead wait until a certain number of players have reported as ready using the command /ready. The server administrator can set the variable g_WarmupReady to a value between 0 and 1 in the server configuration, with g_doWarmup also needing to be set to 1. If g_WarmupReady is set to 0, this means the game will start immediately. At 1, 100% of the present players must enter /ready into the console. Additionally, any other decimal values between 0 and 1 can be entered to force a specific percentage of ready players.

Examples:

set g_doWarmup 1
set g_WarmupReady 0.5 -> 50% must be ready.

set g_doWarmup 1
set g_WarmupReady 0.8 -> 80% must be ready.

This command is particularly recommended for Last Pad Standing and generally for team-oriented game modes.


Last Pad Standing (LPS)

Last Pad Standing comes with a few additional commands g_lps_startlives and g_lps_flags, allowing for some customization of the game mode. g_lps_startlives determines the number of lives each player starts with at the beginning of a round. g_lps_flags can be set to 0, 1 or 2. If the variable is set to 1, players must win multiple rounds of LPS consecutively before one of them reaches the configured point limit. The point limit can be set using the variable pointlimit. If the variable g_lps_flags is set to 2, each player receives multiple points based on their current rank. These points are calculated as the number of starting lives minus the number of currently remaining players with lives plus 1. The advantage of this setting is that players who have many lives will receive many points and players who have few lives will receive few points. Furthermore, new players can join a round later on, giving them a chance to compete for higher positions. If the Varaiable g_lps_flags is set to 0, the game mode is played as usual, without special rules.

Examples:

set g_lps_startlives 8 -> Each player starts with 8 lives.

set g_lps_flags 1
set pointlimit 3 -> A player must win three rounds consecutively, to win.

set g_lps_flags 2 -> Players receive points based on their rank, [number of starting lives] – [number of players with remaining lives] + 1) lives.


Freeze Tag (FT)

This game mode can also be played over multiple rounds on a map. For this purpose, the variable g_ft_numRounds is set to a positive integer representing the desired number of rounds. Once one team has won enough rounds such that the other team cannot catch up in the remaining rounds, the game ends as the winner is practically determined. By setting the variable g_ft_playAllRounds to value 1, it can additionally be enforced that all rounds must be played, even if a team has already been determined as winner. With variable g_ft_lateJoinTime, late joining players can enter during a certain time after game start without immediately getting frozen. For this purpose, positive integer values for seconds need to be defined.

Examples:

set g_ft_numRounds 5 -> A game goes up to five rounds.
set g_ft_playAllRounds 0 -> The game ends when one team has won at least three rounds.

set g_ft_numRounds 5 -> A game goes five rounds.
set g_ft_playAllRounds 1 -> All rounds must be played.

set g_ft_lateJoinTime 15 -> Players can join up to fifteen seconds after game start without immediately getting frozen.


InstaPad

With the variable g_spawnProtect set to a positive integer, the InstaPad modulator can be configured to specify how many seconds players should be protected after respawning, making them invincible. This is useful because newly appearing players typically need some time to orient themselves and can otherwise quickly become targets for other players. As long as the time is running, the lower middle area of the HUD will blink with full health and shield energy.

Examples:

set g_spawnProtect 6 -> Players are protected for 6 seconds.
set g_spawnProtect 3 -> Players are protected for 3 seconds.
set g_spawnProtect 0 -> Players are not protected.
