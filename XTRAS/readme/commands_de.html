Hilfreiche Befehle

Warmup erzwingen

Der Befehl g_WarmupReady kann verwendet werden, damit ein Spiel nicht sofort nach dem Laden startet, sondern erst dann, wenn sich eine bestimmte Anzahl von Spielern sich mit dem Befehl /ready als spielbereit gemeldet hat. Der Serveradministrator kann in der Serverkonfiguration die Variable g_WarmupReady auf einen Wert zwischen 0 und 1 setzen, wobei g_doWarmup ebenfalls auf 1 stehen muss. Wenn g_WarmupReady auf 0 gesetzt ist, bedeutet dies, dass das Spiel sofort gestartet wird. Bei 1 müssen 100% der anwesenden Spieler /ready in die Konsole eingeben. Zusätzlich können alle anderen Dezimalzahlen zwischen 0 und 1 eingegeben werden, um einen bestimmten Prozentsatz an spielbereiten Spielern zu erzwingen.

Beispiele:

set g_doWarmup 1
set g_WarmupReady 0.5 -> 50% müssen spielbereit sein

set g_doWarmup 1
set g_WarmupReady 0.8 -> 80% müssen spielbereit sein

Dieser Befehl wird besonders für Last Pad Standing und generell für teamorientierte Spielmodi empfohlen.


Last Pad Standing (LPS)

Last Pad Standing bringt noch ein paar zusätzliche Befehle g_lps_startlives und g_lps_flags mit, um den Spielmodus ein wenig anpassen zu können. g_lps_startlives legt die Anzahl der Leben fest, mit denen jeder Spieler zu Beginn einer Runde ausgestattet wird. g_lps_flags hingegen kann auf 0, 1 oder 2 gesetzt werden. Wird die Variable auf 1 gesetzt, müssen die Spieler mehrere Runden LPS hintereinander gewinnen, bis einer der Spieler das eingestellte Punktelimit erreicht hat. Das Punktelimit kann über die Variable pointlimit eingestellt werden. Wird die Variable g_lps_flags auf 2 gesetzt, bekommt jeder Spieler mehrere Punkte abhängig von seinem aktuellen Rang. Diese errechnen sich aus der Anzahl der Startleben minus der Anzahl der aktuell vorhandenen Spieler mit Leben plus 1. Der Vorteil dieser Einstellung ist, dass Spieler, die viele Leben haben, viele Punkte bekommen und Spieler, die wenige Leben haben, wenige Punkte bekommen. Darüber hinaus können neue Spieler einer Runde nachträglich beitreten und haben so die Chance, sich nach oben zu kämpfen. Wird die Varaiable g_lps_flags auf 0 gesetzt, wird der Spielmodus wie gewohnt gespielt, also ohne besondere Regeln.

Beispiele:

set g_lps_startlives 8 -> Jeder Spieler startet mit 8 Leben

set g_lps_flags 1
set pointlimit 3 -> Ein Spieler muss 3 Runden für sich entscheiden, um zu gewinnen.

set g_lps_flags 2 -> Die Spieler bekommen Punkte abhängig ihres Rangs, also [Anzahl der Startleben] – [Anzahl der Spieler mit verbleibenden Leben] + 1) Leben.


Freeze Tag (FT)

Dieser Spielmodus kann auch über mehrere Runden auf einer Map gespielt werden. Dazu wird die Variable g_ft_numRounds mit einer positiven ganzen Zahl für die Anzahl der gewünschten Runden gesetzt. Sobald eines der beiden Teams ausreichend Runden gewonnen hat, sodass das andere Team in den verbleibenden Runden nicht mehr aufholen kann, wird das Spiel beendet, da der Gewinner praktisch feststeht. Durch das Setzen der Variable g_ft_playAllRounds auf den Wert 1 kann zusätzlich erzwungen werden, dass alle Runden gespielt werden müssen, auch wenn ein Team bereits als Gewinner feststeht. Mit der Variable g_ft_lateJoinTime können nachträglich beitretende Spieler bis zu einer bestimmten Zeit nach Spielbeginn beitreten, ohne sofort eingefroren zu starten. Hier müssen also ebenfalls positive ganzzahlige Werte für die Anzahl der Sekunden definiert werden.

Beispiele:

set g_ft_numRounds 5 -> Ein Spiel geht bis zu fünf Runden.
set g_ft_playAllRounds 0 -> Das Spiel endet, sobald ein Team mindestens drei Runden gewonnen hat.

set g_ft_numRounds 5 -> Ein Spiel geht 5 Runden.
set g_ft_playAllRounds 1 -> Alle Runden müssen gespielt werden.

set g_ft_lateJoinTime 15 -> Spieler können bis zu 15 Sekunden nach Spielbeginn beitreten, ohne sofort eingefroren zu starten.


InstaPad

Über die Variable g_spawnProtect mit positiven ganzen Zahl kann beim Modulator InstaPad eingestellt werden, wie viele Sekunden Spieler nach einem Respawn geschützt, also unverwundbar, sein sollen. Dies ist nützlich, da sich neu erscheinende Spieler in der Regel erst einmal orientieren müssen und somit schnell zum Kanonenfutter für andere Spieler werden können. Solange die Zeit läuft, blinkt der untere mittlere Bereich des HUDs mit voller Lebens- und Schildenergie auf.

Beispiele:

set g_spawnProtect 6 -> Spieler sind 6 Sekunden geschützt.
set g_spawnProtect 3 -> Spieler sind 3 Sekunden geschützt.
set g_spawnProtect 0 -> Spieler sind nicht geschützt.
